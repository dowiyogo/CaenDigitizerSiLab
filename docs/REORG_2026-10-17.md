## 4. Calendar Calibration for Production Runs (v1–v10)

Because `timestamp` in the `data_dig` tree records microseconds since host boot (`CLOCK_MONOTONIC`), wall-clock calibration was established using the file modification timestamps (`end_mtime`) of stable runs.

1. **Boot Time Calibration**:
   $$\text{boot\_est} = \text{end\_mtime} - \text{last\_timestamp\_us}$$
   Evaluated across stable calibration runs (v2, v3, v5, v6, v8, v9), yielding an extraordinarily tight median reference:
   $$\text{boot\_ref} = 2026\text{-}05\text{-}15\text{T}19:03:28.8\text{ }(-04:00)$$
   (matching the expected reference of 19:03:30 to within 1.2 seconds).

2. **Run v1 Start Correlation**:
